Testing the participant guide

How to preview docs/index.html on your laptop, check it end to end against a workshop VM, and publish it with GitHub Pages. No merge to main is needed for any of it.

1. Preview the guide with Live Server

docs/index.html is a single self-contained file. It loads nothing external; the only outside URLs it builds are the View links to a VM. In VS Code, right-click the file and choose Open with Live Server.

FeatureHow to check it
Copy buttonsClick Copy and paste somewhere. They work on Live Server because 127.0.0.1 counts as a secure origin for the clipboard API.
Done ticks and progress barTick a few steps and reload. They are saved in this browser's localStorage.
Theme toggleSwitch light/dark and reload; the choice is remembered.
VM IP boxType an IP at the top, or open the page with ?ip=<vm-ip>. Every View link then points to http://<vm-ip>/…, and the ssh command shows the IP.
Phone layoutNarrow the window: the sidebar turns into a row of step buttons.

2. Test the full flow against a VM

igv.js is not part of the guide. The IGV page (instructors/scripts/build/files/web/igv.html) and the QC reports are served by Caddy on each VM. The guide only links to them, so they need a running VM.

  1. From instructors/scripts, start the one-user test VM: 
    dovm create dovm/course-test-one-user.yaml --login-user bioseq --login-password-file pw.txt
  2. Open the guide on Live Server and enter that VM's IP in the box at the top.
  3. Run a few pipeline steps over SSH, then click the View links: fastqc, MultiQC, the benchmark report and IGV all load from the VM (log in as bioseq with the shared password).
  4. On the IGV page, check the file list, the Jump to buttons and the soft-clips toggle at the FLT3 ITD.
  5. Tear it down when finished: 
    dovm destroy dovm/course-test-one-user.yaml
Don'topen igv.html itself on Live Server. Its file list comes from the VM's /files/ and /data/ folders behind basic auth, so locally it shows the genome and nothing else.

3. Publish with GitHub Pages

The guide lives in docs/ because Pages, when it publishes straight from a branch, can only use the repo root or the /docs folder. The repo is public, so Pages is free.

  1. Push the branch that holds the version you want to publish (e.g. 2026-upgrade).
  2. In GitHub: Settings → Pages → Build and deployment → Source: Deploy from a branch, then pick that branch and the /docs folder.
  3. After a minute or two the guide is live at https://roysomak4.github.io/ngs_bio_workshop/. Each push to that branch republishes it.

Any branch works, so you can test before merging and switch the source to main afterwards. Only one Pages site exists per repo, so switching the branch replaces what is live.

Mixed content is fineThe Pages site is HTTPS and the VMs are plain HTTP, but the View links open the VM in a new tab rather than embedding it. Browsers only block HTTP content loaded inside an HTTPS page.
Handing out linksAppend ?ip=<vm-ip> to the Pages URL to give each participant a link with their VM already filled in, e.g. https://roysomak4.github.io/ngs_bio_workshop/?ip=203.0.113.10.
